# BI-099 — Cohesive Git history rewrite

## Goal

Rewrite the local linear history into smaller task-focused commits without changing the product tree, architecture, runtime behavior, tests, dependencies, or historical audit claims. Preserve the original history through an explicit archive reference because BI-090 and BI-096 cite exact pre-rewrite commit IDs.

## Boundaries

In scope:

- preserve the original `c6d4b1537b3deeda0d5d1568db97a27394dfd207` tip through `refs/tags/archive/pre-bi099-history`;
- split the largest mixed commits at task or independently reviewable behavior boundaries;
- normalize rewritten commit subjects to `type(scope): outcome (BI-NNN)` where a task ID applies;
- add concise commit bodies describing purpose, boundaries, and validation inherited from the recorded worklog;
- prove that the rewritten pre-BI-099 tree is byte-identical to the original tip;
- retain a linear `main` history and synchronize the project handoff after the rewrite.

Out of scope:

- product, test, dependency, configuration, object-key, manifest, delivery-semantics, or ADR changes;
- editing historical BI-090 or BI-096 audit evidence to pretend that new commit IDs were the audited candidates;
- deleting the original Git objects or archive reference;
- introducing merge commits or rewriting historical worklog text.

## Rewrite strategy

1. Commit this active-task plan before rewriting so the operation starts from a clean worktree.
2. Create the annotated archive tag at the original pre-task tip.
3. Use a root interactive rebase with explicit edit boundaries for the selected oversized commits.
4. Split by task and behavior, keeping directly related implementation, tests, and documentation together where the original cumulative patch permits it.
5. Preserve the exact final tree of every rewritten original commit series; do not manufacture historical test claims beyond the evidence already recorded in `docs/WORKLOG.md`.
6. Run structural history checks and compare the rewritten pre-task tree with the archived original tip.
7. Run repository policy, lint, offline tests, and full verification before task closeout.

## Targeted commits

The primary rewrite targets are:

- `5fce150` — BI-050 REST ingestion;
- `b22c35a` — BI-060 file ingestion;
- `6c42499` — BI-070, BI-080, and BI-090 work combined in one commit;
- `3676b81` — BI-091, BI-092, and BI-093 work combined in one commit;
- `5ee3781` — BI-094 and BI-095 combined in one commit;
- `a4ef6d3` and `f78f753` — BI-096 attestation, lint correction, and terminal backlog policy closeout.

A split is accepted only when its boundary is semantically clearer than the original and the cumulative rewritten tree remains exact. Generated fixtures and tightly coupled contract foundations are not split solely to meet a line-count target.

## Acceptance evidence

- `refs/tags/archive/pre-bi099-history` resolves to the original full tip.
- `main` remains a single-parent linear history.
- Targeted multi-task commits are replaced by task-focused commits with consistent subjects and explanatory bodies.
- The rewritten commit immediately before BI-099 has the same tree ID as the archived original tip.
- `git diff archive/pre-bi099-history <rewritten-pre-task-commit>` is empty.
- Repository policy, `make lint`, `make test`, and `./scripts/verify.sh` pass.
- `tasks/backlog.yaml`, `docs/STATE.md`, `docs/WORKLOG.md`, and this plan record truthful completion and exactly one next atomic step.
