# BI-095 implementation plan — full local configuration preflight

Status: complete; slices 1 and 2 accepted

Dependencies: `BI-090` and `BI-094` are complete; [ADR 0001](../adr/0001-use-garage-for-s3-compatible-storage.md) remains binding

Authority: [product specification](../specification/batch-ingestion.md), the local-environment and clean-start contract in [README](../../README.md), [`BI-090-F05`](../audits/BI-090.md#bi-090-f05), and the canonical BI-095 scope and acceptance criteria in [`tasks/backlog.yaml`](../../tasks/backlog.yaml)

## Objective

Close `BI-090-F05` by making `make check-local-env` and the prepublication check used by `make init-local-env` validate the same complete application configuration accepted by `AppConfig.from_env()`, while retaining the Compose-only local-infrastructure checks that are outside `AppConfig`.

An operator must not receive `PASS` for a dotenv file that a production ingestion command will reject during `AppConfig` loading. Initialization must validate generated content in its owner-only temporary file before `os.replace()`, publish nothing when that validation fails, and leave a valid initialized file byte-for-byte unchanged on rerun.

BI-095 changes no configuration names or defaults, source behavior, retry budget, object key, manifest schema, environment-generation algorithm, delivery guarantee, runtime dependency, or accepted ADR. It aligns one shared local validation boundary and the documentation claim with the already binding `AppConfig` contract.

## Reproduced planning-baseline gap

The current local preflight has two independent surfaces:

- `AppConfig.from_env()` requires and validates PostgreSQL connection settings, S3 endpoint/region/bucket/credentials/addressing/retry/timeouts, the complete HTTP bounds, all file bounds, all snapshot bounds, and `LOG_LEVEL`, including protocol maxima and file/snapshot cross-field constraints.
- `scripts/check_local_env.py` validates only selected Compose ports, local credentials/placeholders, the Garage RPC secret, and three S3 retry/timeout bounds.

`scripts/init_local_env.py` calls that partial `validate_environment()` against its temporary file immediately before publication. Consequently, a dotenv file can omit `POSTGRES_HOST`, every `HTTP_*`, `FILE_*`, `SNAPSHOT_*`, and `LOG_LEVEL` setting and still pass both direct preflight and initialization prepublication validation. A later ingestion command then fails while constructing `AppConfig`, contrary to the README claim and BI-080 acceptance boundary.

The gap is validation coverage, not source connectivity. Full preflight must remain pure: it parses values and constructs typed configuration without opening PostgreSQL, HTTP, or S3 connections.

## Contracts that must not change

- `.env.example` remains the canonical local dotenv template and keeps the existing names and defaults.
- `AppConfig.from_env(values)` remains the single application-level authority for required values, positive/finite numeric checks, absolute credential-free HTTP(S) URLs, port/protocol maxima, addressing style, log level, and file/snapshot cross-field constraints.
- Local-only fields outside `AppConfig` remain explicitly validated: `S3_PORT`, `GARAGE_ADMIN_PORT`, `GARAGE_RPC_SECRET`, and `MOCK_API_PORT`.
- The four recognized credential placeholders remain exactly `POSTGRES_PASSWORD`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, and `GARAGE_RPC_SECRET`; initialization neither invents another placeholder nor rotates a non-placeholder credential.
- Validation receives only the parsed dotenv mapping. It must not fill missing dotenv values from `os.environ`, read a second environment source, or connect to a service.
- User-visible failures name variables or fixed constraints only. They never include credential values, URLs containing credentials, generated values, full mappings, exception representations, or file contents.
- Parsing still rejects malformed and duplicate assignments. Preflight still rejects empty required local fields, recognized placeholders, invalid local ports, and a non-hex/non-64-character Garage RPC secret.
- Initialization still refuses tracked targets, symlinks, non-regular targets, unsafe/unknown placeholders, duplicate assignments, missing parents, and partial credential rotation.
- Generated content is written to a mode-`0600` sibling temporary file, flushed and synced, fully validated, and only then atomically published with `os.replace()`. Every failure removes the temporary file and preserves the prior target bytes or target absence.
- A valid initialized rerun generates no values, changes no bytes, runs the same full preflight, retains mode `0600`, and reports `unchanged`.
- `SOURCE_SEED` remains validated by the existing explicit seed command. Compose project names, wait budgets, and demo supervisor settings are Make/command inputs rather than `AppConfig` dotenv fields and are outside this repair.

## Fixed implementation design

### 1. Reuse `AppConfig` as the application-validation authority

Keep `read_env()` as the simple dotenv parser. Refactor `validate_environment(values)` so it combines two bounded layers:

1. local infrastructure validation for fields not represented by `AppConfig` and for the explicit local placeholder/RPC-secret policy;
2. one explicit `AppConfig.from_env(values)` call over the same parsed mapping.

Catch only `ConfigurationError` from the application-validation call and append its fixed, safe-to-display message. Do not catch arbitrary exceptions and do not render `values`, `repr(config)`, exception causes, or traceback/backend text. Unexpected programming errors must remain visible to tests rather than being mislabeled as configuration failures.

Do not duplicate the full application field list or reproduce numeric/cross-field rules in `check_local_env.py`. Delegation to `AppConfig.from_env()` ensures future application fields cannot silently remain outside local preflight. Existing local checks may use small explicit allow-lists only for the four Compose-only fields and the four recognized secret placeholders.

The effective validated application groups are:

- PostgreSQL host, port, database, user, password, connect timeout, and statement timeout;
- S3 endpoint URL, region, bucket, access key, secret key, addressing style, total attempts, connect timeout, and read timeout;
- mock API base URL plus every `HTTP_*` attempt, timeout, backoff, elapsed, pagination, response-byte, and backfill bound;
- every `FILE_*` byte, spool, record, Parquet-batch, and diagnostic bound;
- every `SNAPSHOT_*` elapsed, row, chunk-count, serialized-byte, and spool bound;
- `LOG_LEVEL`.

### 2. Preserve infrastructure-specific checks without conflicting validation

Reduce the manually maintained application overlap rather than running a second implementation of `AppConfig` rules. `POSTGRES_PORT` and the application S3 bounds are validated by `AppConfig`; `S3_PORT`, `GARAGE_ADMIN_PORT`, and `MOCK_API_PORT` retain the explicit `1..65535` local-port rule. `GARAGE_RPC_SECRET` remains exactly 64 hexadecimal characters.

Placeholder rejection remains a local preflight concern because non-empty placeholder text is structurally acceptable to `AppConfig`. Report only the affected variable name and fixed reason. It is acceptable for the combined validator to return more than one independent safe error, but one setting must not produce duplicate messages from parallel implementations.

`check_local_env.main()` retains its stable exits and headings:

- usage error: exit `2`;
- invalid/missing configuration: exit `1`, `Local environment preflight: FAIL`, then redacted bullets;
- valid complete configuration: exit `0`, one `PASS` line naming only the selected path.

### 3. Keep initialization validation before publication

Continue to inject the same preflight callable into `_write_atomically()`. Because `_default_preflight()` delegates to the expanded `validate_environment()`, generated credentials and all unchanged template settings are validated together before replacement.

Tests must cover both failure states:

- no prior target: invalid template content creates no target and leaves no sibling temporary file;
- existing placeholder target: invalid non-secret application content leaves the original bytes unchanged and removes the temporary file.

For an already initialized target, full preflight failure must also preserve its bytes and emit no success message. A valid second run must preserve exact bytes and must not call credential generation.

No initializer rewrite or new transaction mechanism is required; the existing temporary-write, `fsync`, preflight, `os.replace`, and cleanup sequence already provides the required publication boundary once the validator is complete.

### 4. Align operator wording with the proven surface

Update the Make help text and README environment-setup description to distinguish:

- complete `AppConfig` validation for PostgreSQL, S3, HTTP, file, snapshot, and logging settings;
- additional Compose-only port, Garage RPC-secret, and placeholder checks;
- pure validation only, with no connectivity/readiness claim.

Retain the existing initialization claims about explicit invocation, recognized placeholders, atomic owner-only publication, redaction, symlink/tracked-file refusal, and idempotent rerun. Do not claim that `SOURCE_SEED`, service availability, credentials accepted by a live backend, or arbitrary shell/Compose variables are validated by `check-local-env`.

## Test-first implementation slices

### Slice 1 — Complete redacting preflight (complete)

1. Replace the partial preflight fixture in `tests/unit/test_local_infrastructure_commands.py` with one complete initialized local environment derived from the committed template or an exact test-owned equivalent.
2. Add a failing parameterized omission matrix with at least one setting from PostgreSQL, S3, HTTP, file, snapshot, and logging. Every case must exit `1`, name the missing variable, and print no sentinel values.
3. Add malformed and boundary cases for credential-bearing URL rejection, invalid log/addressing values, non-finite or non-positive bounds, HTTP/snapshot protocol maxima, and the existing Compose-only ports/RPC secret.
4. Add explicit file and snapshot cross-field cases proving preflight rejects the same invalid relationships as `AppConfig`.
5. Implement the minimal delegation from `validate_environment()` to `AppConfig.from_env(values)`, retaining the non-overlapping local checks and stable CLI output.
6. Run focused config/preflight tests, Ruff/format/mypy, and active LSP diagnostics for every changed Python path. Do not change initialization or README behavior in this slice beyond test helpers required by the shared validator.

### Slice 2 — Atomic initializer acceptance, documentation, and closeout (complete)

1. Add initializer tests using invalid full-application settings to prove prepublication rejection for an absent target, byte preservation for an existing target, temporary-file cleanup, no generated-value disclosure, and no success message.
2. Strengthen the valid-rerun case to prove exact byte stability, mode `0600`, full preflight execution, and no credential regeneration. Retain all tracked-file, symlink, duplicate, unknown-placeholder, and partial-rotation tests.
3. Update Make help and README with the exact complete-application plus Compose-only validation surface and explicit no-connectivity boundary.
4. Run focused tests and the complete offline suite. Run Compose rendering, the complete integration suite, and the isolated clean-export walkthrough because every local operational and demo target uses this preflight.
5. Run final LSP and repository gates, mark BI-095 done only after every acceptance row passes, select BI-096 as the sole next atomic task, and synchronize backlog, state, and worklog.

## Non-goals and risks

- No new environment variable, default, secret source, parser dependency, dotenv interpolation, shell expansion, runtime dependency, or ADR.
- No live PostgreSQL, HTTP, S3, Garage-admin, or credential-authentication probe. Readiness remains the responsibility of bounded Compose health checks and integration commands.
- No validation of `SOURCE_SEED` in `AppConfig`; the existing seed-specific validator remains authoritative immediately before seeding.
- No aggregation redesign in `AppConfig`. It may report the first application error; tests cover each required group independently.
- No broad exception conversion. Only `ConfigurationError` is a redacted expected application-validation failure.
- No secret rotation, overwrite of a partially initialized file, or implicit `init-local-env` invocation from operational targets.
- No BI-096 clean-commit attestation and no Possible extensions.
- The full validator imports application configuration code but performs no network or service I/O. Tests must fail if that boundary regresses.

## Documentation basis

Planning used the repository's current `AppConfig.from_env()` implementation and tests as the application configuration authority, the existing standard-library atomic initializer, the Compose-only local fields in `.env.example`, and the finalized `BI-090-F05` reproduction. No external library API changes are required, so Context7 lookup is not needed for this planning task.
